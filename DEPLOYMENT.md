# Deploying Kabadiwala Connect

This project deploys as **two services**:

| Part | Platform | What it is |
|---|---|---|
| **Frontend** (`frontend/`) | **Vercel** | Static Vite + React build |
| **Backend** (repo root) | **Render** | Express API + cron jobs, talking to Supabase Postgres |

The database is your existing **Supabase** project — nothing to provision, the API just connects to it.

Deploy the **backend first** (the frontend needs its URL), then the frontend, then wire CORS.

---

## Prerequisites

- The code pushed to GitHub (this repo).
- Your Supabase **connection string** — Supabase Dashboard → Project → Settings → Database → **Connection string → URI**. Use the **Session pooler** (port `5432`) or **Transaction pooler** (port `6543`, append `?pgbouncer=true`).
- Free accounts on [Render](https://render.com) and [Vercel](https://vercel.com).

> The schema and demo data are already in your Supabase project. If you ever point at a fresh database, run `npm run db:setup` then `npm run db:seed` locally against it once.

---

## 1. Backend → Render

This repo includes [`render.yaml`](render.yaml), so Render can set everything up automatically.

1. Render Dashboard → **New +** → **Blueprint**.
2. Connect this GitHub repo. Render detects `render.yaml` and shows the **kabadiwala-connect-api** web service.
3. Click **Apply**. It will ask for the env vars marked as secrets:
   - **`DATABASE_URL`** → your Supabase URI from above.
   - **`CORS_ORIGIN`** → leave blank for now (you'll set it in step 3).
4. Wait for the build (`npm install && npx prisma generate`) and first deploy to finish.
5. Confirm it's healthy — open:
   ```
   https://<your-service>.onrender.com/api/health
   ```
   You should see `{ "success": true, "database": "connected", ... }`.

Note your service URL, e.g. `https://kabadiwala-connect-api.onrender.com`.

### Backend environment variables

| Variable | Set by | Value |
|---|---|---|
| `DATABASE_URL` | you (secret) | Supabase connection URI |
| `CORS_ORIGIN` | you (step 3) | Your Vercel URL, e.g. `https://kabadiwala-connect.vercel.app` |
| `JWT_SECRET` | Render (auto-generated) | — |
| `NODE_ENV` | blueprint | `production` |
| `JWT_EXPIRES_IN` / `BCRYPT_ROUNDS` | blueprint | `7d` / `12` |
| `SMS_PROVIDER` | blueprint | `console` |
| `CLOUD_STORAGE_PROVIDER` | blueprint | empty (local disk) |
| `AI_SERVICE_ENABLED` | blueprint | `false` |
| `PRICE_TREND_CRON` / `MODEL_RETRAIN_CRON` | blueprint | cron schedules |

## 2. Frontend → Vercel

This repo includes [`vercel.json`](vercel.json), which builds the app from `frontend/` and adds SPA routing — **no "Root Directory" change needed**.

1. Vercel Dashboard → **Add New** → **Project** → import this GitHub repo.
2. Leave the build settings as detected (they come from `vercel.json`).
3. Add an environment variable:
   - **`VITE_API_BASE_URL`** = your Render URL **+ `/api`**, e.g.
     ```
     https://kabadiwala-connect-api.onrender.com/api
     ```
   > This is read at **build time**. If you change it later, redeploy the frontend.
4. **Deploy.** Note the resulting URL, e.g. `https://kabadiwala-connect.vercel.app`.

---

## 3. Connect them (CORS)

1. Back in Render → your service → **Environment** → set **`CORS_ORIGIN`** to your exact Vercel URL (no trailing slash):
   ```
   https://kabadiwala-connect.vercel.app
   ```
2. Save — Render redeploys automatically.
3. Open the Vercel URL and sign in with a demo account (see the README's *Demo logins*).

Done. 🎉

## Free-tier caveats (important for a demo)

- **Cold starts:** Render's free web service **spins down after ~15 min idle**. The first request then takes ~30–60s to wake. The health check and first login may feel slow — that's expected.
- **Uploaded photos aren't permanent:** Render's free disk is **ephemeral** — files written to `./uploads` are wiped on every redeploy/restart. Images uploaded during a session work while the instance is alive. For permanent images, set `CLOUD_STORAGE_PROVIDER=imagekit` and the three `IMAGEKIT_*` keys on Render (the code in [`config/cloudStorage.js`](config/cloudStorage.js) already supports it).
- **Cron jobs only run while awake:** `PRICE_TREND_CRON` / `MODEL_RETRAIN_CRON` fire only when the instance is up. On free tier they may be skipped during sleep. Upgrade the plan or use Render Cron Jobs if you need guaranteed schedules.

---

## Security checklist

- **Never commit `.env`.** It's gitignored. All secrets go in the Render/Vercel dashboards.
- Because this repo is public, **rotate your Supabase database password** (Supabase → Settings → Database → Reset password) and update `DATABASE_URL` on Render. Do the same for any key that has been in a local file.
- `JWT_SECRET` is auto-generated by Render — you don't need to manage it.

Unchanged — see the [README](README.md). Locally the frontend leaves `VITE_API_BASE_URL` unset and Vite proxies `/api` and `/uploads` to `http://localhost:3000`.
